# Episode-based video sources

The Anilife, Linkani and Ohli24 adapters are adapted from the user-supplied `Plugins.zip` package (Lua API1, version 0.2.7a1). Phrolova uses native Python adapters instead of installing a Lua runtime or executing uploaded scripts.

In **Videos**, select a source and paste a work or episode URL. Work links open an episode picker with search, pagination, unavailable-file status and a limit of 100 selected episodes. Selection adds separate tasks to the existing queue, preserving its quality controls, pause/cancel, persistence, remuxing and media inspection. Valid VTT subtitles are saved beside the video.

| Source | Work | Episode |
| --- | --- | --- |
| Anilife | `https://anilife01.tv/content/<work>` | `/content/<work>/<episode>`; numbered `anilife[0-9]+.tv` hosts are accepted |
| Linkani | `https://linkani.tv/ani/<work>/` | `/watch/<work>/a<source>/k<number>/` |
| Ohli24 | `https://www.ohli24.net/<id>/<title>.html` (`ohli24.net` also accepted) | Same URL shape; the page determines whether it is a work or episode |
| TVWiki (티비위키) | `https://tvwiki54.net/<category>/<work>` | `/<category>/<work>/<episode>`; categories include drama, ent, movie and animation |
| TVChak (티비착) | `https://tvchak208.com/index.php/vod/detail/id/<work>.html` | `/index.php/vod/play/id/<work>/sid/<source>/nid/<episode>.html` |
| Animaru (애니마루) | `https://animaru1.com/content/<work>` | `/content/<work>/<number>`; `/contents/` aliases, special episode 0 and fractional numbers are normalized |
| Ani365 (애니365) | `https://v2.ohli365.org/?title=<UUID>` | Phrolova adds `&episode=<registered-UUID>` after episode selection; `&episode=movie` selects an advertised movie |

Ani365 reads the selected work and its registered episodes from literal JSON chunks in the page's Next.js data. It does not evaluate page scripts or guess episode identifiers. Selection calls the site's normal public `/api/home/playback` endpoint and verifies the returned episode/response identity before using its advertised MegaPlay player. Public player URL metadata is decoded locally; no browser runtime or account cookie import is required.

The HLS server requires the player's origin and root referrer on both manifests and media. Every quality playlist is validated, and the advertised same-episode fragment paths are resolved on the verified issuing server, which serves those same assets. Rotating CDN aliases are not contacted. Validated media playlists are passed directly to yt-dlp's native HLS downloader, preserving the checks between extraction and transfer. Standard HLS encryption uses the existing key checks; unsupported/protected formats and advertisement tags remain rejected. Captions are accepted only as valid VTT files for the same media identity and saved in the languages actually provided by the player.

The October 16, 2026 Ani365 check retrieved a 10-episode catalog and downloaded a complete 1,370.036-second episode through the actual VOD engine without a cookie file. The final 359,344,925-byte MKV contains 1920×1080 H.264 video and AAC audio, with nine separate VTT subtitle files. Media inspection and full FFmpeg decoding passed with no errors. Browser integration retained all 16 sources and verified work selection, query-based episode queueing, invalid URLs and 320/390/768/1440-pixel layouts.

A second live-site work returned 23 registered episodes and 1080p/720p/360p formats. Its different manifest/fragment naming and hashed English VTT filename were verified through extraction and a bounded MPEG-TS fragment probe. Subtitle paths remain restricted to the selected media identity; language comes from the filename or the player's label.

Only listed episodes are returned. Linkani lists that omit earlier episodes carry an explicit incomplete-list notice; missing episodes are never guessed. Work/episode identity and Ohli24 parent breadcrumbs are checked again before extraction. Site JavaScript is parsed only as normal JSON data, never evaluated.

Numbered website addresses are recognized by parsing the URL and matching its entire hostname: `animaru[0-9]+.com`, `tvchak[0-9]+.com`, `tvwiki[0-9]+.net` and `anilife[0-9]+.tv`. The supplied hostname is preserved in canonical URLs, episode selection, preparation and website request headers. Website redirects may change the number within the same family; other domains, lookalike suffixes, credentials, non-HTTPS URLs and nonstandard ports are rejected. Playback/session APIs stay pinned to the actual website host, and player/CDN allowlists remain separate. This recognizes a supplied address; it does not search for new domains.

Animaru uses the public reader API referenced by its own web application, preserving actual episode numbers, unavailable entries and declared incomplete catalogs. The selected API entry must lead to an allowed player whose advertised playlist has the same player ID. Standard HLS keys, every playlist reference and provided VTT subtitle identities are checked before the existing queue downloads, remuxes and inspects the media. A missing optional subtitle does not discard a valid video. Public reader/player extraction was verified without a cookie file; no authentication control or challenge is automated.

The October 16, 2026 Animaru check retrieved 15 registered episodes and downloaded a complete 1,370.094-second episode through the actual VOD engine without a cookie file. The final 346,225,942-byte MKV contains 1920×1080 H.264 video and AAC audio; its Korean VTT subtitle was saved separately. Media inspection and full FFmpeg decoding passed with no errors. Browser integration retained all 15 sources and verified special/fractional episode URLs, direct episode queueing, the mobile source list and 320/390/768/1440-pixel layouts.

Ad detection examines playlist tags instead of arbitrary substrings of media filenames. A real Animaru segment named `VaSTCAY0CX.dat` exposed the previous false positive. Ad cue/daterange/SCTE/VAST tags and protected key methods remain rejected, while ordinary randomized segment names continue through the native HLS downloader.

TVChak uses the page's actual `content_playlist` episode links and `player_aaaa` JSON data. Work, source and episode IDs must match before media is accepted. Direct MP4 files use a bounded range probe, the site's player referer, the existing resumable downloader, local remuxing and media inspection. The interface offers the original rendition when the site does not advertise separate quality variants. Standard HLS on the explicitly allowed media host uses the existing manifest validation and native downloader. Ads, paid/previews, unrelated hosts and changed player identities are rejected.

An optional **TVChak** cookie card is available in **Settings → Authentication**, with `TVCHAK_COOKIE_FILE` for source installations. Cookies must belong to a numbered `tvchak[0-9]+.com` domain. Each request uses only that exact website's cookies; cookies from an older number are not copied to a new domain or sent to the MP4 CDN. Access-check responses, including HTTP 202, are reported as access errors rather than empty catalogs. Open the site in a browser using the server's internet connection and register its Netscape cookie export when the site requests verification. The application does not solve challenges or claim that file registration validates access.

The October 16, 2026 check confirmed the live site's work/episode structure in a normal browser and downloaded a 10.11-second, 7,193,194-byte sample from its declared MP4 server. The sample contained 1920×1080 H.264 video and AAC audio and passed a full FFmpeg decode. Unauthenticated server requests to the site pages returned an AWS access check (HTTP 202), so a complete unauthenticated page-to-download run could not be verified on this connection. Local integration tests cover real MP4/HLS queue downloads, preparation, remuxing/inspection, cookie scope and registration/removal, access errors, all 14 source choices and mobile layouts.

Requests use HTTPS, bounded responses and explicit site/player/CDN allowlists. Redirect destinations and every manifest reference are checked. Cookies from normal player issuance stay within one extraction/download session, including the transition from metadata extraction to actual media transfer; credentials from other platforms are not borrowed.

TVWiki is a separate Videos source. Its catalog uses the site's actual episode links, with duplicate thumbnail links removed. The adapter follows the current guest session and player configuration requests, parses configuration data without executing site JavaScript, and validates the issued HLS playlist and its resources. It prefers the player's advertised native/casting HLS rendition and registers its ordinary guest session on that rendition's issuing host. Standard 16-byte AES-128 keys use the existing native downloader and local remux/inspection pipeline; browser-specific key decoders are not executed. A denied site/player response is reported as an access error.

If an advertised TVWiki CDN fragment fails, the downloader retries that exact playlist resource on the issuing media server, preserving its path and query. This retry applies only to validated playlist resources and media hosts, strips explicit cross-host credentials, and keeps the existing cookie jar's domain rules. A failed CDN host is avoided for subsequent fragments of the same task; unavailable fragments are never silently skipped.

The October 16, 2026 TVWiki check retrieved a 14-episode public catalog and downloaded a complete 1,375.354-second episode through the actual VOD engine, including origin recovery for blocked CDN fragments. The final 631,200,903-byte MKV contains 1920×1080 H.264 video and AAC audio, passed media inspection, and completed a full FFmpeg decode with no errors. Tests also cover native guest-session issuance, key validation, origin/resource boundaries, encrypted local HLS downloads, all 13 source choices, episode-to-queue requests, and 320/390/768/1440-pixel layouts.

Some connections reset before the site's HTTPS handshake finishes. In that case the site client retries the same allowed host once, splitting the TLS ClientHello across standard TLS records. The original certificate/hostname verification, cookies and proxy settings remain in use. HTTP errors, certificate failures and resets while reading an HTTP response do not trigger this retry; a session-creation POST is never repeated after it has been sent.

Anilife's current guest player first posts to `/api/playback/session`, then requests playback with the issued proof and its matching HttpOnly cookie. Phrolova follows this normal guest-session flow, renews an expired proof once, and sends proof headers only to the issuing API host. Numeric and fractional episode selectors are resolved against the site's catalog. Guest proofs and cookies are kept on the server.

Ohli24 supports the `michealcdn.com` and `cdndania.com` players, the bounded `ohli[1-7]ncloud[1-5]-nocdn.xyz` and `tue[1-7]bcloud-starcdn.xyz` CDN families, and the older `hol[1-7]ncloud2-nocdn.xyz` hosts. The same HTTPS and redirect checks apply to both players. A title containing an unescaped question mark can be resolved using its numeric content ID instead of rejecting the site's own link.

HLS validation accepts ordinary AES-128 with `KEYFORMAT="identity"` and version `1`. Unsupported/protected key formats, malformed or duplicate key attributes, advertising playlists and unfinished live playlists are rejected. The original Lua package's browser-session fallback is not automatically installed; HTTP access failures are reported in the interface.

Validation includes strict URL/redirect tests, all three source parsers, Unicode URLs, episode identity, guest proof/cookie renewal, API-header scope, VTT subtitles, normal AES-128 and encrypted local-media downloads through the actual yt-dlp queue and FFprobe inspection. Session-protected local HLS downloads test all three adapters. Browser tests cover 11 sources, API failures, selection limits, queue payloads, fractional episode selectors, host aliases and 320/390/768/1440px layouts.

TLS recovery tests include real local HTTPS with a trusted certificate, rejection of an untrusted certificate and a mismatched hostname, connection reuse, cookie persistence, proxy-pool preservation and a reset followed by exactly one real session-creation POST. Record splitting preserves every handshake byte and leaves unrelated hosts and application-data records unchanged.
