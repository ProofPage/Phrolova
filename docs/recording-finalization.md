# Streamlink 녹화와 종료 후 파일 변환

라이브 연결과 TS 쓰기는 `YtdlpLivePipeline`의 Streamlink 리더가 담당한다. 라이브 데이터를 FFmpeg로 전달하지 않는다. 이전 `FFmpegPipeline` 이름은 동일한 Streamlink 클래스의 호환 별칭이다. 미리보기와 VOD 엔진에서 사용하는 FFmpeg는 별도 경로다.

```
플랫폼 상태·화질 조회 → Streamlink → .ts.part
→ 리더·파일 핸들 종료 → .ts 확정 → 변환 대기
→ FFmpeg -c copy → 임시 MKV/MP4 → FFprobe 검사
→ 덮어쓰기 없이 최종 파일 확정 → 녹화 이력 갱신
→ 보관 설정이 꺼진 경우에만 원본 정리
```

CHZZK, YouTube, SOOP, CIME는 이 경로를 공유한다. 플랫폼마다 URL·인증·화질을 가져오는 어댑터는 유지한다. YouTube는 공개 접근을 먼저 시도하고 인증 오류일 때 저장된 쿠키 사본을 사용한다. SOOP의 준비 구간 필터와 CIME 메타데이터·HLS 처리는 플랫폼 어댑터에 남긴다.

HLS TS 영상은 직접 저장한다. 별도 음성 렌디션은 별도 원본 파일에 저장하며 종료 후 영상과 함께 stream copy한다. DASH 전용·fMP4/CMAF 영상은 TS로 위장해 저장하거나 라이브 FFmpeg로 변환하지 않고 지원 오류를 표시한다.

## 설정과 마이그레이션

- 전역 출력은 MKV/MP4, 원본 보관 기본값은 켜짐, 동시 변환 기본값은 1개다. 최대 3개로 설정할 수 있다.
- 신규 설치 기본값은 MP4다. 명시된 기존 `LIVE_FORMAT=ts/mkv/mp4`는 보존한다. 기존 TS 사용자는 설정 변경 전까지 TS만 유지한다.
- 채널별 `output_format=null`은 전역 상속이다. MKV/MP4는 채널별 재정의다.
- 형식과 보관 정책은 녹화 시작 시 작업에 저장한다. 이후 설정 변경은 현재 작업을 바꾸지 않는다.
- SQLite 스키마 v5는 `app_settings`, `recording_jobs`, `channels.output_format`, `live_history.recording_job_id`를 추가한다. 기존 테이블·파일·이력을 삭제하지 않는다.
- 제거된 플랫폼의 DB 행과 옛 JSON 캡처 메타데이터는 이관·조회 호환용으로 남는다. 해당 플랫폼의 감시와 실행은 하지 않는다. 기존 채팅 파일도 지우지 않는다.

## 실패와 복구

일시적인 연결 EOF는 오류/재연결로 처리하며 같은 TS 임시 파일에 이어 쓴다. ENDLIST 또는 사용자의 중지, 방송 종료 확인, 재연결 한도 초과 때만 쓰기를 종료한다. 파일 핸들이 닫히지 않으면 후처리를 등록하지 않는다.

변환은 인자 배열로 실행하며 `shell=True`를 쓰지 않는다. `-c copy`로 코덱·해상도·FPS를 유지하고 MP4에는 `+faststart`를 적용한다. FFmpeg 진행 출력으로만 진행률을 계산하고, 길이를 모르면 백분율을 만들지 않는다. stderr는 비밀 값을 가린 최대 64 KiB를 보관한다. 종료 코드 0 외에도 컨테이너·스트림 수·코덱·해상도·FPS·길이·크기를 확인한다.

실패, 검사 오류, 저장 공간 오류, 서버 종료 때 원본은 남긴다. 임시 변환 파일도 재검사에 사용할 수 있도록 남긴다. 원본이 있는 작업은 다시 변환하거나 MKV로 재시도할 수 있다. 성공 후 원본을 정리한 작업도 최종 파일을 다시 검사할 수 있다. 기존 최종 파일은 덮어쓰지 않는다.

재시작 때 미완료 녹화·변환·검사 작업은 확인 필요로 복원한다. 닫힌 변환 대기 작업은 다시 큐에서 실행한다. 원본을 확인한 뒤 재시도하면 새 임시 출력 파일로 작업한다. 변환 큐는 감시 중지와 별개로 유지하고, 서버 종료에서는 실행 중인 FFmpeg를 종료·회수한다.

## API와 UI

| API | 기능 |
|---|---|
| GET/PUT `/api/recordings/settings` | 전역 출력 정책 |
| GET `/api/recordings/jobs` | 현재·과거 파일 처리 작업 |
| POST `/api/recordings/{id}/retry` | 다시 변환, 선택적 MKV/MP4 변경 |
| POST `/api/recordings/{id}/inspect` | 다시 검사 |
| GET `/api/recordings/{id}/file` | 등록된 작업 파일 열기 |
| POST `/api/recordings/{id}/open-location` | 서버 폴더 열기 또는 저장 경로 안내 |

라이브 카드 아래에서 변환 대기, MKV/MP4 변환 중, 파일 검사 중, 완료, 변환 실패를 확인한다. 이전 작업과 제거한 채널의 작업도 파일 처리 이력에서 관리한다. 설정 화면과 채널 녹화 설정에서 형식을 변경한다. 채팅·오디오 보관함 메뉴와 전용 API·인증·수집 태스크는 제거했다.

## 실행 환경

실행 파일은 설정 경로, 번들, PATH, Termux의 `PREFIX/bin`을 탐색한다. 후처리는 이벤트 루프 밖의 검사와 비동기 FFmpeg 프로세스를 사용한다. 하드 링크가 불가능한 파일시스템에서는 배타적 복사·fsync로 게시하며, 실패한 부분 출력만 정리하고 원본은 보존한다. Linux/Termux GUI가 없으면 저장 폴더 경로를 안내한다.

검증 범위와 실제 플랫폼·운영체제에서 수행하지 않은 항목은 별도 최종 검증 보고서에 기록한다.
