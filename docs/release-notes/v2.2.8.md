# Phrolova v2.2.8

## Platform and stream pipeline enhancements

- **YouTube live pipeline**:
  - Fix false offline detection caused by video player UI text markers, ensuring active streams are accurately detected and recorded.
  - Reduce stream extraction latency by eliminating an unnecessary request sleep interval.
  - Reduce unnecessary playlist requests and improve HLS reception resilience by aligning playlist reload intervals to the live edge, using single-threaded segment fetching, and extending timeout margins.
  - Prefer lightweight 480p/360p streams for live previews to prevent playback stalls.
  - Support dynamic resolution and frame rate querying for all platforms in channel settings.
- **RPLAY error handling and stream recovery**:
  - Treat transient HTTP 404 and server errors as stream-unavailable recovery conditions, not proof that a broadcast ended or authentication is missing.
  - Keep RPLAY monitoring active during server recovery and recheck after 60 seconds without exhausting the normal recording retry counter.
  - Clear recovery status after a successful recording start.
- **SOOP platform integration**:
  - Add live channel monitoring, recording, VOD downloads, and authentication settings for SOOP.
  - Validate channel and VOD links and keep authentication cookies scoped to their original domains.
  - Resolve live preview manifests and supply the required playback headers through the preview proxy.
  - Distinguish channel lookup failures from offline broadcasts, close stream discovery sessions, and report unavailable quality selections.

## Fallback downloader and dependencies

- Keep yt-dlp as the primary VOD downloader. Invoke N_m3u8DL-RE independently only after an eligible, already-resolved single HLS VOD download fails.
- Prevent arbitrary external `yt-dlp.exe` binary downloads by enforcing Python package imports.
- Remove unsupported yt-dlp external-downloader injection that could break HLS downloads.
- Offer separate interactive installation for the optional downloader and detect its standard installation directory.
- Detect FFmpeg and FFprobe across standard Windows directories and user-extracted version folders.

## Interface and build pipeline

- Upgrade GitHub Actions workflow dependencies to eliminate Node 20 deprecation notices.
- Provide dynamic quality detection and refresh for YouTube, SOOP, and all supported platforms.
- Remove automatic browser launch at startup while preserving the manual system tray shortcut.
- Remove the topbar notification icon and notification center.
- Include channel configuration alignment and authentication layout improvements.
- Show connection stages and recent reception events in recording details.
- Reset consecutive retry counters after a successful reconnect so intermittent server errors do not accumulate into a permanent recording block.
- Use consistent recovery and failure labels in channel cards, recording details, and connection history.
- Stop showing stale write speeds after reception stops and prevent completed or idle recordings from retaining a receiving/reconnecting stage.
- Cover RPLAY access-denied monitoring recovery without requiring session reimport when access becomes available again.
- Automatically repair single-stream H.264/AAC TS timestamp discontinuities and backward clock jumps during postprocessing without transcoding, preventing decode errors while preserving exact stream start offsets.
- Treat YouTube reception ending while broadcast status is being checked as informational, rather than immediately reporting a recording-reception failure.
- Preserve the existing application layout and themes; no experimental UI redesign is included.

## Saved-file integrity checks

- Add an on-demand check for completed, available recording files using full FFmpeg decoding and SHA-256.
- Reject active recordings, concurrent checks, and files changed during inspection.
- Display capture observations separately from saved-file decoding results.
- A passing check verifies the saved file only. It does not prove that every part of the original broadcast was received or that the recording is identical to the complete source.

## Distribution

- Publish a Windows x64 portable executable and SHA256 checksum.
- Manage as a single consolidated v2.2.8 release.
