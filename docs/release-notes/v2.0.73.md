Restore episode-site access when the network resets the initial HTTPS connection. This release retains the guest-session, cookie-transfer and player/CDN fixes from v2.0.72.

## Changes

- When an allowed site resets its connection before HTTP transmission, retry that host once with the TLS ClientHello split across standard TLS records. This recovered Anilife, Linkani and Ohli24 catalog/playback access in the tested network.
- Keep the original certificate and hostname verification, proxy settings, cookie jar and request data. Apply the compatibility transport only to the affected host. Certificate failures, HTTP 401/403 responses and response-read failures do not trigger this retry.
- Preserve the session-creation boundary: a POST is retried only after a pre-HTTP connection reset. Requests that reached the HTTP stage are not replayed by this mechanism.
- Continue using native HLS for episode downloads before local MP4 remuxing, including CDN segment URLs with non-media extensions.

## Validation

- Backend regression suite: **1,194 passed, 2 skipped**, with 4 subtests passed.
- TypeScript, production build and translation validation passed.
- Eighteen TLS recovery tests cover actual verified local HTTPS, an untrusted certificate, a mismatched hostname, cookie persistence, connection reuse, proxy-pool preservation, bounded retries and exactly one real session-creation POST after a simulated initial TLS reset.
- A TVWiki-backed Anilife episode downloaded all **685 HLS fragments** into a **699,204,092-byte 1920×1080 H.264/AAC MP4**, lasting **22 minutes 50 seconds**. FFprobe and five-second decode checks at the beginning, middle and end passed.
- Anilife and Linkani each downloaded a complete 94-second 1080p H.264/AAC episode through Phrolova's preparation/download engine and passed media inspection. Ohli24 passed a 10-second 1080p native-HLS download and inspection.
- The Windows executable is checked for the release version, bundled TLS/episode fixes, frontend assets, transparent round icons, Windows Defender results and SHA-256 checksum before publication.

## Upgrade

Finish active recordings/downloads and stop Phrolova before replacing the executable. Preserve your `.env`, `data` directory and media. Source installations can update to this tag and restart; this change requires no settings migration.
