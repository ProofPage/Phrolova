# Phrolova v2.0.91

## Twitch recording stability
- Show advertisement waiting separately from other recording warnings. Do not treat an active advertisement with fresh upstream activity as a stalled connection.
- Propagate failed segment reception to the existing recording recovery path instead of silently accepting incomplete input.
- Split source files at exact byte boundaries after skipped advertisements or discontinuities, and start a separate part on reconnection.
- After capture closes, remux compatible sequential parts in order without re-encoding or duplicating audio/video tracks. Preserve the original parts; incompatible track layouts are not merged automatically.
- Keep the opt-in proxy and account-token forwarding behavior from v2.0.90 unchanged. It remains disabled by default. Enabling it sends the registered Twitch login token to the external proxy operators.

## Platform selectors
- Fit live and video platform selectors to the selected name rather than a fixed 120px width.
- Keep an 8px gap between the name and arrow, without clipping or horizontal page overflow in the checked layouts.

## Validation
- Local full backend run: 2,002 passed, 2 skipped and 4 subtests passed.
- Browser checks: 648 platform selections across eight languages and 320px, 897px and 1440px layouts passed.
- Advertisement exclusion, capture boundaries, failed segments and sequential remuxing were exercised with isolated fixtures.
- A short real humzh capture confirmed 1920×1080 video at an advertised 60 fps and AAC audio. Natural long advertisement transitions were not verified with the updated implementation.
- TypeScript/build and eight-locale checks passed. Existing upstream deprecation and bundle-size warnings remain.
