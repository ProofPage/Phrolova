# Version 2.0.55

Improve source-stream handling, recording recovery and live/video settings.

## Recording

- Prefer TS with Streamlink and retain native fMP4 when TS is unavailable. Normalize and remux with FFmpeg only after capture closes, then inspect with FFprobe.
- Prevent path collisions, duplicate channel starts, ineffective retry loops and processing history for empty files.
- Start the recording timer only after data arrives and preserve sources on processing/inspection failure.
- Improve YouTube JavaScript runtime discovery, cookie forwarding and authentication errors.

## Settings and interface

- Default new installations to MKV, forced CHZZK Time Machine and five concurrent downloads; preserve saved preferences.
- Add CHZZK live CDN selection and platform cookie uploads.
- Move storage paths and monitoring intervals into the corresponding video/live settings.
- Use consistent MKV - Matroska / MP4 - MPEG-4 output labels.
- Separate broadcast state from recording controls; improve progress, metrics, completion times, inspection guidance, quality choices and bottom-aligned grid actions.
- Remove icons before sidebar menu names.

## Validation

Windows backend: 685 passed, 6 environment-dependent skips. TypeScript and production build passed. Chromium covered 14 download grid/list combinations and registration, quality, start, pause, resume, cancel and reinspection with isolated API responses. Long external broadcasts and Android device execution were not revalidated for this release. Windows publication uses Actions, Defender and `SHA256SUMS.txt`.
