# Phrolova v2.0.84

This release fixes RPLAY live playlist parsing and expired-session recovery, verified with authenticated production live and VOD samples longer than three minutes.

## Fixes

- Repair missing line separators between quality variants in the official RPLAY BytePlus HLS master. Preserve signed playback URLs.
- Refresh both the API authorization header and live viewer query credentials after access-token renewal, and propagate the updated session to subsequent playback requests.
- Retry RPLAY VOD metadata with the refreshed account parameters.
- Run live token renewal outside the asynchronous event loop.
- Retain server-enforced quality permissions, reject untrusted delivery destinations and avoid forwarding account authorization headers to media servers.

## Validation

- All 96 focused RPLAY live and VOD tests passed, including real Streamlink parsing of the malformed master, renewal, credential isolation, recording and download checks.
- Production live capture: 196.03 seconds saved, with video and audio, followed by a normal stop.
- Production VOD sample: 185.03 seconds saved, with video and audio.
- These are bounded sample checks, not a complete VOD download or an hours-long recording test.

## Usage

Use **Settings → Authentication → RPLAY** to sign in or import a valid session. Browser sign-in does not authenticate the separate Phrolova server. Playback still requires the account permissions granted by RPLAY; unavailable or unauthorized qualities remain excluded.

## Known limitation

The tested YouTube live and video requests still received a bot-verification response, and yt-dlp reported the supplied account cookies as no longer valid. This release does not claim to fix that network/account restriction.

Download `Phrolova-v2.0.84-windows-x64.exe`. The release workflow builds the single executable, scans it with Windows Defender and publishes `SHA256SUMS.txt`.
