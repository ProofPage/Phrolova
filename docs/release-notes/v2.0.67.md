# Version 2.0.67

## What's new

- Add yt-dlp to Settings → Information with the version and installation path of the executable Phrolova actually uses. Expand Installation Path to inspect long paths on desktop or mobile.
- Inspect yt-dlp with a read-only version command; opening Information never downloads or updates it. Distinguish missing tools, execution failures and failed status requests.
- Simplify the startup heading to the application name and version.
- Rewrite the repository overview and README in English, covering supported sources, platform-specific installation, configuration, backups, tool diagnostics and development.
- Standardize all 53 earlier release descriptions in English, repair formatting and preserve versioned copies in the repository. Historical notes continue to describe their original versions.

## Installation and update

- **Windows x64:** Download `Phrolova-v2.0.67-windows-x64.exe` and `SHA256SUMS.txt` below. Finish active work, exit Phrolova and replace the executable in the same folder. Keep `.env`, `data/`, `logs/`, `bin/` and media directories.
- **Linux, macOS and Termux:** Update an authorized source checkout with `phrolova update`, or follow the [README](https://github.com/ProofPage/Phrolova/blob/v2.0.67/README.md). The `.exe` is Windows-only.
- FFmpeg and FFprobe remain separate installations. Existing settings, databases, media paths and recording/download engines are preserved.

## Validation

- Windows backend: **960 passed, 2 skipped, 4 subtests passed**.
- TypeScript, production build and all 840 translation entries in each of eight locales passed.
- Browser integration checked automatic tool inspection, yt-dlp version/path display, long-path wrapping, update actions, failed requests and recovery at 320/768/1440px.
- English documentation checks covered 56 Markdown files, 74 local links and all 53 historical release descriptions.
- The Windows package is checked for native version/icon resources, bundled files, Windows Defender detections and SHA-256 integrity before publication. Validation is performed locally on Windows; see the release pull request for GitHub Actions status.
