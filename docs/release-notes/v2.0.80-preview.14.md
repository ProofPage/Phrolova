# Phrolova v2.0.80-preview.14

Preview release fixing TikTok live video player startup stalled by non-zero FLV stream PTS and resolving preview error translation fallback.

### Key Changes
- **TikTok Real-time Video Player Startup & PTS Synchronization**:
  - Automatically synchronizes video playback `currentTime` to the buffered live edge on stream packet arrival, preventing Chromium and WebView2 from indefinitely stalling when FLV stream PTS starts at non-zero timestamps (e.g. tens of thousands of seconds).
  - Switched `mpegts.js` demuxer to direct main-thread execution (`enableWorker: false`) with `liveSync` enabled, preventing Blob URL Web Worker silent instantiation failures in sandboxed desktop WebView environments.
  - Replaced container `hidden` attribute with opacity and pointer-events overlay so video elements remain active in the rendering tree without browser frame throttling.
  - Fixed missing i18n key (`live.couldNotLoadThePreview` → `live.previewUnavailable`), preventing "문구를 표시할 수 없습니다." from displaying when preview requests encounter connection retries.

- **Inherited from Earlier Previews**:
  - Dedicated video player for TikTok live previews without static frame fallbacks.
  - Encapsulated pure ES module packaging for `mpegts.js`.
  - Prioritized browser-compatible H.264 video streams for TikTok live previews.
  - Fixed SQLite `recording_jobs.source_path` unique constraint collision on recording restart.
  - Bilibili preview resolution and CDN failover optimization.
  - Eliminated CHZZK "재연결 중" / "녹화 중" false-alarm status flickering.
  - Remux duration inspection tolerance for live stream TS discontinuities.
  - Instant guest CHZZK preview resolution without initial 502 errors.
  - Automatic RPLAY session renewal via IndexedDB `refreshToken`.
