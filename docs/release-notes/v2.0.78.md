Add RPLAY live/video support and fix settings persistence, credential recovery and Windows installation errors found during a repository-wide review.

## Changes

- Add **RPLAY (알플레이)** to Live and Videos: validated channel/video links, monitoring, advertised HLS qualities, Streamlink recording, local previews, video preparation and the existing download queue, output conversion, media inspection and history.
- Import an explicit RPLAY session JSON in **Settings → Authentication**. Check the website's playback grant and separate live UHD permission. Never grant playback from a denied API response or send API authorization to unrelated hosts. Browser sign-in alone does not authenticate the separate server.
- Keep **11 live platforms**, **18 video source choices** and **898 translation keys across eight languages**. Preserve all existing sources and responsive dashboard layouts.
- Fix authentication, notification and first-run settings that previously reported success when `.env` could not be saved. Apply runtime changes after successful persistence and validate notification inputs before changing any values.
- Restore the previous cookie/session file when saving a replacement or removal fails. Avoid duplicate cookie writes during setup and report the real authentication state after cookie removal.
- Stop the Windows source installer on missing npm, failed dependency installation or failed frontend build. Require Node.js 22+ consistently with the source installation guide.
- Update the English README and add the [RPLAY support guide](https://github.com/ProofPage/Phrolova/blob/main/docs/rplay-support.md).

## Validation

- Run the complete backend regression suite, critical Python static checks, dependency checks, eight-language validation, TypeScript and the production frontend build.
- Inject filesystem failures through the actual HTTP endpoints to verify that failed authentication replacement/removal, CHZZK updates, notifications and initial setup preserve previous settings and credentials. Execute the actual Windows batch installer with npm failure/success fixtures and paths containing spaces.
- Exercise RPLAY grant validation, expiry, credential scope, quality selection, real local HLS transfer, 1080p Streamlink capture, remux, FFprobe inspection, history restoration and browser integration at 320, 390, 768 and 1440 pixels.
- The supplied RPLAY video played at **1920×1080** in the authenticated browser for about one minute with no media error. The supplied live page loaded a **1280×720** player, but continuous production live playback was not established. Native guest requests correctly reported permission requirements. An authenticated native production recording/download was not tested because no RPLAY session file was imported into the isolated server; synthetic local media tests verify the native transfer pipeline.
- Build the Windows executable through GitHub Actions and run Windows Defender before publication. Publish the executable with its SHA-256 checksum.

## Upgrade

Finish active recordings/downloads and stop Phrolova before replacing the executable. Preserve `.env`, `data`, uploaded credentials and saved media. Source installations can update to this tag and restart; no settings migration is required. Register an account session only for RPLAY content that your account can already view.
