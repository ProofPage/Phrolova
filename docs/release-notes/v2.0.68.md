Add Kick live recording and video downloads, with shared authentication and quality selection, and improve the YouTube extraction pipeline.

## Kick

- Add Kick to Live and Videos, including channel URL validation, platform badges, logging and all eight interface languages.
- Use Streamlink's Kick plugin and HLS reader for live stream resolution and recording. Support monitoring, previews, actual quality lists, and manual/automatic recording.
- Download Kick VODs and clips through yt-dlp, using the existing queue, progress controls, persistence and media inspection.
- Register, replace, inspect and remove Kick cookies under Settings → Authentication → Kick. Apply registered cookies to both live and video extraction so sign-in-only qualities can be discovered.
- Keep explicitly requested 1080p or higher resolutions exact: unavailable quality reports an error instead of silently saving a 720p file. Refresh live qualities or retry video metadata after changing cookies.
- Scope cookies to Kick and bearer authorization to HTTPS Kick API requests. Disable unrelated Streamlink cookie caches and keep credentials out of CDN headers and API responses.
- Distinguish access denial, throttling, deleted content and unavailable quality from an offline channel.

## YouTube

- Apply Node/EJS runtime settings to metadata as well as downloads and channel imports.
- Use the app's installed yt-dlp in isolated live workers, including the Windows package, to avoid mismatches with an external CLI. Terminate and reap cancelled workers.
- Include the official October 2026 client update, retain upstream client selection, preserve anonymous extraction sessions, and pace requests/downloads.
- Start public previews without account cookies; keep optional authentication for restricted content. Separate bot challenges and request limits from account-permission errors.

The submitted public YouTube URLs still returned a bot challenge on the tested VPS, including with a PO-token provider. This release does not claim to resolve that server-network restriction.

## Validation

- Backend regression suite: **1,003 passed, 2 skipped**, with 4 subtests passed; final cookie-scope/VOD checks also passed (51 tests).
- Real public Kick live capture: approximately 12 seconds of H.264/AAC MPEG-TS, verified with FFprobe.
- Real public Kick VOD: the complete 592-second sample downloaded as MP4 (about 47.3 MB), with video/audio inspection passed.
- Authenticated quality and credential-scope behavior was checked with isolated fixtures. A real signed-in Kick 1080p download was not tested because account cookies were not supplied.
- TypeScript, frontend production build, all 849 translation keys in eight languages, and Chromium cookie/quality/queue flows at 360, 390, 768 and 1440 pixels passed.
- The attached Windows executable is built from the release commit and checked for its version, bundled extractors, icons, checksum and Windows Defender detections.

## Upgrade

Finish active recordings/downloads and stop Phrolova before replacing the Windows executable. Preserve your `.env`, `data` directory and media. Source installations should update their dependencies; Termux uses `backend/requirements-termux.txt`.

After updating, register Kick cookies in Settings → Authentication if you need sign-in-only qualities, then refresh the quality list or retry video metadata. Other platform authentication remains unchanged.
