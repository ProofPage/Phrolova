# Phrolova v2.0.83

This release adds account sign-in to four more platforms while preserving cookie-file import, existing RPLAY authentication and normal server-side account and viewing checks.

## Account Sign-In

Open **Settings → Authentication** and choose the platform:

- **CIME:** email and password for the site's MCO integrated account.
- **HearHeart:** email and password.
- **PandaTV:** username and password.
- **PopkonTV:** username and password.

The application follows each official site's sign-in protocol. CIME sign-in completes the MCO callback and confirms the CIME account session; PandaTV checks the issued session through its account endpoint; HearHeart uses its server-issued CSRF token and signed login component; PopkonTV registers the site's issued account and refresh tokens in the existing cookie format.

## Credential Handling

- Account passwords are used for the requested sign-in only and are not persisted. The password field is cleared after every attempt.
- Register only issued cookies scoped to the selected platform; never copy MCO gateway cookies into the CIME cookie file.
- Keep previous credentials if authentication, session verification or atomic credential storage fails.
- Preserve cookie upload, status checks, deletion and RPLAY session import.
- Reject untrusted authentication destinations and upgrade the official CIME callback to HTTPS before requesting it.
- Prevent duplicate sign-in requests while a platform login is already running.

Social-only accounts, CAPTCHA, additional verification and account restrictions may require signing in on the official website and importing its cookies. The application does not solve or bypass these checks.

## Validation

- **Backend regression coverage: 1,980 passed, 2 skipped.** The expected public API list was updated for the intentional new sign-in endpoint; all four API surface checks then passed.
- Browser checks passed for all four account forms, outgoing payloads, password clearing, preserved sessions after failure, disabled controls during sign-in, cookie-import availability and **320–1440px** layouts.
- Frontend production build and all **eight languages** passed validation.
- Real provider endpoints rejected deliberately invalid test credentials.
- **Successful sign-in with production accounts has not been verified.** Successful session issuance, verification, credential scoping, failure handling and storage rollback are covered by mocked protocol tests.

## Download

Download `Phrolova-v2.0.83-windows-x64.exe` and verify it against `SHA256SUMS.txt`.

The Windows release workflow builds the x64 single-file executable, scans it with Windows Defender and publishes its SHA-256 checksum. Keep `.env`, `data/`, `logs/`, `bin/` and recording folders when replacing the executable. FFmpeg and FFprobe remain external dependencies.
