# Phrolova v2.0.85

This release adds bounded RPLAY live and preview recovery when a playback playlist returns HTTP 401 or 403.

## Fixes

- Request a fresh playback grant from RPLAY after a live playlist authentication failure, then retry once without resetting the active HLS worker or its sequence tracking.
- Stop repeated authentication failures if the newly granted playlist is also rejected. Account access and available qualities remain controlled by RPLAY.
- Renew registered RPLAY preview root playlists after HTTP 401/403. Keep browser-facing URLs opaque and validate the renewed media destination against the platform CDN boundary.
- Do not guess unsigned playback addresses, change accounts or renew arbitrary preview segment URLs.

## Validation

- 254 focused backend tests passed, covering RPLAY playback, renewal, credential boundaries, previews, recording recovery, shutdown, capture and finalization.
- Production AWS IVS live capture: 434.01 seconds saved with video and audio and a normal stop.
- Production BytePlus live capture: 438.05 seconds saved with video and audio and a normal stop. Both captures overlapped for approximately five minutes.
- Production IVS preview: 43 successful playlist requests.
- Production VOD sample: 305.03 seconds of 1920x1080 H.264 video and AAC audio saved to MP4.

## Validation limits

The production 403 reported by the user did not recur during these samples. No preview URL renewal was needed in the production run; 403 recovery is verified with mocked responses. A short-lived initial IVS admission URL does not by itself prove that an established stream must stop when that URL expires. These samples are not a complete VOD download or an hours-long recording test.

YouTube bot-verification restrictions observed with the supplied account cookies are not resolved by this release.

## Usage and download

Register a valid RPLAY account session under **Settings → Authentication → RPLAY**. Browser sign-in does not authenticate the separate Phrolova server.

Download `Phrolova-v2.0.85-windows-x64.exe`. The Windows release workflow builds the single executable, scans it with Windows Defender and publishes `SHA256SUMS.txt`.
