# Phrolova v2.1.6

## Live recording reliability and expanded video sources

### Live recording
- Serialize concurrent RPLAY authentication renewals and validate media destinations without copying authentication queries across CDN origins.
- Refresh RPLAY startup playback information instead of reusing stale playlists.
- Confirm Twitch broadcast status with a fresh API request when no playback variants are available.
- Treat an API-confirmed end during RPLAY or Twitch startup as normal monitoring, while preserving genuine connection and authorization errors.
- Split original captures at stream discontinuity boundaries and preserve source files and capture diagnostics.
- Do not count failed media writes as successful segments. File validation and capture continuity are reported separately.

### Video sources and player
- Add TVRoom and Toonday URL recognition, episode selection and download integration.
- Add TVHot URL recognition, catalog lookup and playback-session integration.
- Correct anime source propagation, metadata identifier handling and season selection; improve subtitle and player handling.
- Add source labels in all eight interface languages.

### Validation
- Full backend regression suite: **2,088 passed, 2 skipped** before the release-version update.
- Frontend production build and eight-language resource validation passed.
- Toonday: a **10.01-second** sample downloaded through the application pipeline, with H.264 video, AAC audio and successful full-sample decoding.
- TVRoom: an 8-second sample download and video/audio inspection passed.

### Known limitations
- **TVHot downloads are not verified:** catalog lookup and playback-session creation succeed, but the external player currently returns **HTTP 403** to the application's HTTP client. This release does not bypass that restriction.
- Recording fixes cannot restore segments already missing from an upstream stream. Long-duration live-broadcast validation remains outstanding.

### Download and upgrade
- Download `Phrolova-v2.1.6-windows-x64.exe` and verify it against `SHA256SUMS.txt`.
- Wait for active recordings and finalization jobs to finish before replacing the executable.
- No running installation or recording is replaced automatically.
