# Phrolova v2.2.3

## Termux compatibility

- Publish recording files without overwriting existing files when `os.link` is unavailable.
- Migrate legacy databases without hard links while preserving the original database.
- Install missing Deno through `pkg install -y deno` on Termux and reuse an existing Deno 2+ runtime.

## Authentication settings

- Introduce a shared Liquid Glass-inspired visual layer for buttons, navigation, tabs, toolbars, and dialogs. Keep data, video and inputs on readable surfaces.
- Respect reduced-motion, reduced-transparency and high-contrast preferences, with opaque fallbacks where backdrop blur is unavailable.

- Keep browser cookie import available in account-login mode.
- Place the sign-in action next to its inputs and separate guidance, alternative authentication tools, and status management.
- Distinguish cookie-file registration from a remotely verified login. Local file checks no longer imply a successful login.
- Exclude expired cookies and unrelated domains during browser import.
- RPLAY continues to use session JSON export/import rather than cookie import.

## Workspace redesign

- Refresh the shared navigation, page hierarchy, spacing, buttons, forms, and panels around a content-first desktop and mobile workspace.
- Put platform selection beside the authentication form on desktop and in a compact horizontal selection area on mobile.
- Separate settings categories from their content on desktop, retaining a scrollable category row on smaller screens.
- Add concise page guidance in all eight languages and bring important live/download metrics closer to the page heading.
- Preserve pasted cookie input after failed validation, support keyboard dismissal and focus restoration, and retain existing save/retry/navigation safeguards.

## Anime hub removal

- Remove the `/anime` page, navigation entry, dedicated settings tab, and `/api/lilac` API.
- Preserve existing content, user data, and general video-download functionality.

## Validation scope

Automated tests include isolated data and mocked APIs. They do not establish successful installation or bgutil token generation on a physical Termux device, or successful real-account authentication on every platform.

The Windows executable is published only after the release workflow passes regression tests, packaging, and a Windows Defender scan.
