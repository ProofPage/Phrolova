# Phrolova v2.1.8

More resilient CHZZK playback handling, clearer server errors and safer virtual-environment recovery.

## Changes

- **CHZZK CDN recovery:** adds an `ex-nlive-streaming.navercdn.com` → `livecloud.akamaized.net` candidate probe alongside the existing `nvelop-livecloud.pstatic.net` fallback. Analysis of 200 public live playback responses observed four hosts: `nvelop-livecloud.pstatic.net`, `ex-nlive-streaming.navercdn.com`, `fcdn-livecloud.pstatic.net` and `livecloud.pstatic.net`. Playlist and media responses were checked on supported paths; this is not a guarantee for every broadcast or connection.
- **Signed playback URLs:** removes LL-HLS polling parameters `_HLS_msn` and `_HLS_part` while preserving path-based `hdntl` authorization and its encoded ACL, including the Akamai URL form observed during VPN playback. Expired credentials and HTTP 403 remain access errors; authorization is not bypassed.
- **Server error handling:** improves validation errors, non-JSON responses, network failures, timeouts and cancellation, with credential masking in displayed errors.
- **Safer Windows environment recovery:** virtual-environment backup names no longer depend on the system's date format. If backup fails, installation stops and preserves the original environment rather than deleting it.
- **Twitch defaults:** TTV-AB ad blocking is **off for new settings**. Existing saved settings remain unchanged. The optional third-party quality proxy is a separate setting; its [credential-sharing warning](https://github.com/ProofPage/Phrolova/blob/main/README.md#authentication-and-security) still applies.

## Compatibility and verification

The supported runtime/build baseline is **standard-GIL Python 3.14.8+**. Older Python versions and free-threaded execution are not supported. Installers preserve incompatible virtual environments before replacing them.

At commit [`ed72ffca1842481084b3507fdd9cffb1b1a9e12f`](https://github.com/ProofPage/Phrolova/commit/ed72ffca1842481084b3507fdd9cffb1b1a9e12f):

- [CI run 39541641103](https://github.com/ProofPage/Phrolova/actions/runs/39541641103) passed **all nine jobs**: Python 3.14.8 backend checks on Linux x64/ARM64, Windows x64 and macOS Apple Silicon/Intel; the Termux requirements profile on Linux ARM64/Python 3.14; experimental Python 3.15 checks on Linux and Windows; and frontend locale checks, TypeScript and production build.
- **Python 3.15 remains experimental**, despite both jobs passing. These results do not guarantee compatibility with every environment or future dependency update.
- The Termux-profile check runs on Linux, **not Android**. Android ABI compilation, device behavior and background recording under power management still require device validation.
- [Windows release run 39542830547](https://github.com/ProofPage/Phrolova/actions/runs/39542830547) passed the full Windows backend test suite, frontend checks/build, PyInstaller executable build and Windows Defender scan, and published the executable and checksum file.

Automated tests and targeted playback checks are not full production end-to-end validation of every source or account-restricted workflow. Provider permissions, DRM, bot challenges and rate limits still apply.

```text
e259e9296d34b4bf13cdf18fa779c11fd5078b6a011dd3b2ca06b34b05caa94a  Phrolova-v2.1.8-windows-x64.exe
```

The Windows package includes Python and Node.js; no separate Python installation is needed. **FFmpeg and FFprobe remain external requirements.** Keep the app in a writable folder.

Before upgrading, finish active work, stop Phrolova and back up configuration, the whole data directory and required media. Replace the Windows executable in its existing folder while retaining `.env`, `data/`, `logs/`, `bin/` and media. Source users should follow the [update instructions](https://github.com/ProofPage/Phrolova/blob/main/README.md#updates-and-backups) and the [Linux](https://github.com/ProofPage/Phrolova/blob/main/docs/linux-guide.md), [macOS](https://github.com/ProofPage/Phrolova/blob/main/docs/macos-guide.md) or [Termux](https://github.com/ProofPage/Phrolova/blob/main/docs/termux-guide.md) guide, using the baseline above.

The dashboard/API has **no built-in login**. Keep `127.0.0.1` binding; use an SSH tunnel or protected remote access rather than an unprotected public endpoint.
