# Phrolova v2.0.81

This release improves PopkonTV playback, session renewal and password-protected broadcasts, and fixes an AES-HLS initialization-cache issue.

## PopkonTV
- Enable **Record according to the server playback response** by default. Broadcast types are no longer rejected locally before requesting a server-authorized playback URL. Login and viewing-permission checks remain enforced.
- Reload broadcast metadata and imported login credentials on each connection, preventing stale account or playback state after a broadcast restarts.
- Renew expired live and VOD sessions through the official refresh-token API instead of attempting password-based re-login. Persist rotated credentials atomically and share concurrent refreshes.
- Add a broadcast-password field to channel recording settings. Passwords are kept only while the app is running, excluded from settings responses and not written to configuration files. Enter them again after restarting.
- Preserve API-only credential scoping and media-host validation. A server denial is not treated as a playback grant.

## CHZZK AES-HLS
- Key decrypted initialization data by its encryption key and IV context, rather than only by the initialization URL and byte range.
- Cover key rotation, IV changes, encrypted/clear transitions, native HLS and LL-HLS capture, and preservation of original media bytes.

## Validation
- Backend regression suite: **1,921 passed, 2 skipped**.
- Browser checks passed for playback-policy persistence, password entry, input validation, retry/skip states and responsive layout.
- Frontend build and all eight translation resources passed validation.
- Recording tests use local media and mocked platform responses. The browser investigation separately confirmed authorized PopkonTV live playback.

## Encryption Scope
The separately investigated CHZZK videos marked `encryptionType: "AES"` can use a DASH-SEA manifest and a cookie-authenticated key endpoint. This release does **not** add dedicated handling or claim verified end-to-end compatibility for that playback/key-discovery flow. The AES-HLS regression tests above must not be interpreted as that compatibility claim.

## Download
Download `Phrolova-v2.0.81-windows-x64.exe` and verify it against `SHA256SUMS.txt`.

The Windows release pipeline builds the single-file executable, scans it with Windows Defender and publishes its SHA-256 checksum. Keep your existing configuration, imported cookies and recordings when replacing the executable.
