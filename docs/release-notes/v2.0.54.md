# Version 2.0.54

Separate live capture from post-recording processing, add SOOP/CIME integration and refine the dashboard.

## Recording and recovery

- Capture TS directly with Streamlink. After recording fully stops, remux to MKV/MP4 with FFmpeg and inspect with FFprobe, without re-encoding by default.
- Configure global/per-channel output format, source TS retention and processing concurrency. Settings are fixed for a recording when it starts.
- Preserve sources on processing failure; support reinspection, reconversion and MKV fallback. Persist processing jobs and recover them after restart.

## Platforms and interface

- Integrate SOOP/CIME detection, cookies, qualities, previews and downloads alongside CHZZK/YouTube. Accept CHZZK channel IDs and links.
- Consolidate download input, remove duplicate metrics and align cards, badges, progress and actions in grid/list/mobile layouts. Support Full HD previews.
- Remove the empty media-hub menu and redundant recording path/processing explanations while keeping job status and file controls.
- Remove chat collection/storage/viewing and X Spaces execution. Existing files and historical records are retained.

## Upgrade and validation

This version defaults to MP4 with source TS retention and preserves existing format settings. Its capture support is TS HLS; DASH-only and fMP4/CMAF sources are reported as unsupported in this version.

Backend regressions, real local Streamlink HLS capture, MP4/MKV remuxing, FFprobe inspection and a 3.59 GB TS conversion were checked. Chromium covered card actions, settings and responsive layouts; TypeScript/build checks passed. Long upstream broadcasts, restricted content and Linux/Android device execution were not exercised locally. Windows publication uses Actions and Defender.

Finish recordings/downloads and stop the app before replacing it. Keep configuration, databases and media. Windows uses the attached executable; Linux/Termux use source.
