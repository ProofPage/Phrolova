# Version 2.0.60

## Recording shutdown and recovery

- Drain the active segment and receive buffers before finalizing a stopped recording.
- Preserve sources from cancelled, forcibly terminated or incomplete capture without reporting normal completion.
- Carry the last checkpoint and bounded disk buffer across CHZZK reconnects/file transitions to recover missing intervals.
- Flag damaged-packet warnings separately even when the resulting file remains playable.

## Video downloads

- Validate TS/fMP4 structure in HLS/DASH fragments before merging them.
- Retain HTTP causes such as 403/404 and bound request/scheduling queues during widespread failures.
- Improve vertical-video quality selection, filename/part-path restoration after restart and long Korean/Windows paths.

## Dashboard and defaults

- Align live cards and expanded previews, retaining a 16:9 offline area.
- Improve channel monitoring recovery and state updates.
- Default new CHZZK live/video jobs to Akamai, with consistent Naver CDN / Akamai CDN labels; preserve saved choices.
- Remove long job IDs from new recording filenames without renaming/deleting existing files.

## Validation

- Backend: 866 passed, 1 skipped, 4 subtests passed.
- Windows x64, Ubuntu x64/ARM64 backend CI and frontend type/build checks passed.
- Chromium processing/download actions and responsive checks passed.
- Two public CHZZK captures passed TS normalization, MKV finalization and FFprobe inspection.

Existing Streamlink/yt-dlp engines, settings, databases and source recordings are preserved; FFmpeg/FFprobe remain external. Of 148 reference issues, 17 require further device/account/storage testing. Native Termux/proot endurance was not marked as validated.
