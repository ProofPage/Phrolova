# Version 2.0.52

- Unify Windows executable metadata, tray, npm identity and packaging under Phrolova.
- Build dist/Phrolova.exe with phrolova.spec; keep the versioned Windows x64 release asset format.
- Use phrolova commands, phrolova.service and ~/Phrolova for new Linux installations.
- Detect existing installation directories and command links; restore prior systemd state if service migration fails.
- Use phrolova.db; back up legacy rookery.db or signal_recorder.db including committed WAL data. Preserve originals and use the original on migration failure.
- Preserve settings, media, license attribution and existing Streamlink -> FFmpeg live recording, yt-dlp VOD, CDN and playback behavior.

Validation: 500 Python tests passed; npm ci, TypeScript, production build, Chromium UI/player regressions and local Linux streaming/download/restart tests passed.
Windows executable is CI-built and Defender-scanned. Interactive Windows tray/startup, real systemd boot, Android Termux/ARM64 devices and external CHZZK downloads remain unverified for this release.
See https://github.com/ProofPage/Phrolova/blob/v2.0.52/docs/rebranding-audit-ko.md for migration details and test limits.

Before updating, finish recordings/downloads, stop all old instances and back up settings/data. Keep legacy DB originals; never run old and new versions against separate database snapshots simultaneously.
Windows: replace the stopped executable in the same directory; preserve .env, data, logs, bin and media.
Linux/Termux: use source archives and https://github.com/ProofPage/Phrolova/blob/v2.0.52/docs/linux-guide.md or https://github.com/ProofPage/Phrolova/blob/v2.0.52/docs/termux-guide.md. The exe is Windows-only.
