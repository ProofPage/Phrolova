# Phrolova v2.0.82

This release improves CHZZK live Time Machine recording without adding a bandwidth or replay-speed cap, introduces dedicated AES-HLS discovery for encrypted CHZZK VODs and updates the project documentation.

## CHZZK Live Time Machine
- Share matching in-flight media requests between foreground recording and recovery instead of downloading the same segment twice.
- Bound recovery work to available network workers rather than filling a separate background queue.
- Stop recovery-only capture after the complete missing interval has been delivered, and preserve the shared recovery deadline until then.
- Use whole segments during Time Machine catch-up rather than speculative partial copies.
- Isolate long-lived recording readers from the shared asynchronous executor, preventing blocked media reads from starving other channels or control operations.
- Preserve original media and file-boundary handling. There is no fixed MB/s cap or artificial catch-up multiplier.

Time Machine records an ongoing live broadcast from the history CHZZK actually provides. Some broadcasts expose up to 3,600 seconds; others provide a shorter window. A start offset of zero means the earliest available segment, not a guarantee of the broadcast's beginning.

## CHZZK AES Playback
- For VOD metadata marked `encryptionType: "AES"`, read the dedicated playback manifest and select the platform-advertised AES-128 HLS rendition instead of attempting unsupported DASH-SEA downloading.
- Keep native key requests in the normal account cookie jar. Live AES key credentials are sent only to the official HTTPS CHZZK API origin and are not forwarded to media CDNs.
- Keep server login/viewing decisions and unsupported-protection errors intact.

Register valid Naver cookies in Phrolova when the key server requires an account. Signing in to a browser does not authenticate the separate Phrolova server.

## Documentation
- Refresh the README and repository description for the current ten live platforms; remove the obsolete SOOP listing from the repository description.
- Document uncapped live catch-up, server-dependent replay windows, CIME UHD, RPLAY direct login and PopkonTV session renewal/password rooms.
- Distinguish supported HLS live capture from SABR-only/DASH-only YouTube inputs.

## Validation
- **97 focused backend tests passed**, including complete one-hour moving-window fixtures, encrypted live/VOD media, credential scoping, recovery sharing and independent recording readers.
- A real **1920×1080** live capture received the full one-hour backlog and reached the live edge in about **72 seconds**. Two channels then recorded concurrently for another two minutes and stopped cleanly, without missing or duplicate segment checkpoints.
- Both native files contained H.264 video and AAC audio and passed FFprobe inspection. The one-hour capture includes 3,794 seconds of original media including subsequent live segments.
- Frontend production build and all eight translation resources passed.
- Real encrypted VOD metadata and 144p/720p/1080p quality discovery were checked. Authenticated keys and exact decrypted media bytes are covered by local fixtures; **a complete account-authenticated production encrypted VOD download has not been verified** in the release environment.

Catch-up throughput depends on the CDN, network and disk. The measured live test is not a guaranteed catch-up time or a claim of zero internet latency.

## Download
Download `Phrolova-v2.0.82-windows-x64.exe` and compare it with `SHA256SUMS.txt`.

The release workflow builds the Windows x64 single-file executable, scans it with Windows Defender and publishes its SHA-256 checksum. Keep `.env`, `data/`, `logs/`, `bin/` and recording folders when replacing the executable. FFmpeg and FFprobe remain external dependencies.
