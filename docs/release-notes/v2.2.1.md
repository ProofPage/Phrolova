# Phrolova v2.2.1

## Rplay live recording reliability

- Serialize session-token refresh requests across channels and reuse the latest saved token after another channel refreshes it.
- Use the latest rotated refresh token when the saved access token also needs renewal.
- Reject stale refresh requests after an account change instead of overwriting the newly configured account.
- Move synchronous session loading and refresh work off the asynchronous event loop so one channel's authentication does not block other channel tasks.
- Prefer the authorized `livestreamUrl` over `playUrl` when falling back from BytePlus playback.
- Explicitly refresh stream metadata when renewing an expired playback URL.

## Cookie authentication interface

- Block already registered live channels when adding them, with an immediate notice and a server-side conflict response.

- Fix the missing save-button translation and use translated cookie-input guidance in all eight supported languages.

## Validation

- Regression coverage includes 12, 16, and 24 concurrent session refreshes and live-status requests, account changes, and rotated refresh tokens.
- These concurrency tests use controlled fixtures; they do not claim long-duration recording validation against 24 real broadcasts.
