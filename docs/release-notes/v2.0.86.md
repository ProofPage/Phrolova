# Phrolova v2.0.86

This release fixes RPLAY renewal failures, stabilizes CHZZK recording statistics, prepares YouTube runtime tools automatically and simplifies the authentication screen.

## RPLAY recovery

- Fix the `property 'url' ... has no setter` failure by updating Streamlink request arguments rather than assigning its read-only URL property.
- Exercise renewal with real guarded Streamlink objects, including repeated renewal, denied grants and untrusted destinations.
- Surface failed segments and mid-response disconnects to recording recovery rather than silently dropping them. Preserve the error's retry policy.
- Both supplied AWS IVS channels saved approximately 4 minutes 8 seconds while a playlist 403 was deliberately injected. Recovery then used real RPLAY grants and real media requests. This was a controlled fault, not a naturally recurring server refusal.

## CHZZK statistics

- Separate media bitrate from bursty disk-write throughput.
- Average CHZZK write speed over the segment interval advertised by its playlist, not an arbitrary two-second interval. Genuine stalls still fall to zero.
- No recording bandwidth cap, quality reduction or video re-encoding is added.
- A real standard live capture with Time Machine disabled saved 166.71 seconds of 1080p video and audio. Write speed sampled 0.51–0.93 MiB/s and media bitrate approximately 6.2 Mbps. The native source was preserved and stream-copied into MKV for inspection.

## Automatic YouTube tools

- On first launch, download Deno 2.9.7 and bgutil server/plugin 2.0.2 into persistent `data/youtube-tools`, verifying pinned SHA-256 hashes.
- Check and reuse healthy installations on subsequent launches instead of downloading or installing again.
- Prepare tools in the background so unrelated platform monitoring can start. Installation failures are logged and are not recorded as successful.
- Bind the managed provider only to `127.0.0.1:4416`. Reuse a matching server, retain an explicitly configured external provider and stop only the process owned by Phrolova.
- Apply the official `youtubepot-bgutilhttp:base_url` option and shared runtime/plugin paths to video downloads, live resolution, previews and channel imports.
- A native Windows installation, restart with installation skipped, local server health and real token generation were verified.

Initial setup requires internet access and can take several minutes. Windows, macOS and GNU/Linux x64/ARM64 assets are supported; native Android/Termux requires a compatible manually prepared runtime/provider. Working tools or successful token generation do not guarantee that YouTube will accept the account or network connection.

## Authentication UI

- Collapse platform cards by default, with two columns on desktop and one on mobile.
- Separate account sign-in, cookie-file import and RPLAY session-JSON import.
- Consolidate shared guidance and distinguish credential registration from per-stream viewing permission in all eight languages.
- Correct login success notifications, clear passwords after attempts and when closing or switching methods, and retain cookie/session import and export help.

## Validation and download

- Full backend regression before the final statistics change: 2,009 passed, 2 skipped.
- Final CHZZK/pipeline regression: 109 passed, with 4 subtests passed.
- Authentication browser tests, keyboard interaction, 320–1440px layouts, all eight locale checks and frontend production build passed. The existing bundle-size warning remains.
- Download `Phrolova-v2.0.86-windows-x64.exe` and verify it against `SHA256SUMS.txt`. The release workflow scans the executable with Windows Defender.
