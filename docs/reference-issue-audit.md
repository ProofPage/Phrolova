## 이번 통합 변경

- Streamlink 라이브와 yt-dlp VOD를 유지한다. 동적 48-thread Qt 엔진을 복사하지 않는다.
- #321/#334/#329/#131: decoded fragment 구조 검사, 최초 HTTP 원인 보존, bounded 예약 큐, 제한 재시도.
- #318/#336: portrait 짧은 변 목록/selector 일치, 동일 크기 최고 비트레이트 선택 회귀.
- #190/#323: 재시작 resume identity 복원, UTF-8/Windows 전체 경로 예산, 임시 suffix/충돌 여유.
- #185/#183/#192: 수신 데이터 drain 후 확정, 중지/손상 실패를 attention으로 보존, 버퍼 세션 인계, 변환 성공과 녹화 무결성 구분.
- UI/설정/미리보기 선행 수정은 같은 브랜치 기반 PR #8 변경을 포함한다. 이번 PR에서 버퍼/종료/VOD 검증을 추가했다.

## 미완료 환경의 처리

#136/#137은 OS 네트워크 파일 쓰기가 반환하지 않는 실제 mount가 필요하다. #219는 기존 상대경로 설정을 서로 다른 cwd에서 복구하는 추가 시나리오가 필요하다. 과거 실제 URL/멤버십/연령 제한/앱 충돌 항목은 해당 계정·유효 영상·플랫폼 실기가 없으므로 E로 남겼다. 원본 삭제·무제한 스레드·전역 TLS 검증 비활성화로 우회하지 않았다.

참고 저장소의 열린 항목을 닫힌 것으로 취급하지 않았다. #336/#333처럼 Phrolova 구조상 동일 결함이 재현되지 않은 항목도 입력 회귀를 추가했고, #334처럼 다른 경로에서 같은 사용자 오류가 나타나는 항목은 B로 실제 수정했다.
